# Руководство по настройке Nginx для Xray-Reality / 3x-ui

Данный конфигурационный файл предназначен для защиты вашего Xray/VLESS сервера, маскировки его под легитимный веб-сайт (в данном случае стриминговый сайт `animesss.com`) и обеспечения безопасного доступа к панели 3x-ui и подпискам клиентов.

## ⚠️ Важное предупреждение перед запуском

Конфигурация содержит строгие правила безопасности и маршрутизации. Для ее успешной работы необходимо убедиться, что ваша инфраструктура настроена соответствующим образом.

### 1. SSL Сертификаты (Критично)
Вам необходимо получить и разместить SSL-сертификаты для вашего домена **`yourdomane.online`** до запуска Nginx. Без них конфигурация не запустится.
*   **Пути в конфиге:**
    *   `/root/cert/yourdomane.online/fullchain.pem`
    *   `/root/cert/yourdomane.online/privkey.pem`
*   Если вы используете Let's Encrypt (Certbot) или Acme.sh, обновите пути в блоках `server` конфигурации на реальные пути к вашим сертификатам (например, `/etc/letsencrypt/live/yourdomane.online/fullchain.pem`).

### 2. UNIX Сокеты (Взаимодействие с Xray и Nginx)
Конфигурация использует локальные UNIX-сокеты (в оперативной памяти `/dev/shm/`) для максимальной производительности и скрытия портов:
*   `unix:/dev/shm/xray-reality.sock` (и `xray-reality2.sock`) — Сюда Nginx направляет трафик Reality (на основе SNI-масок, например, `taxi.yandex.ru`). **В вашей панели 3x-ui (или конфиге Xray) Inbound для Reality должен слушать именно этот сокет, а не IP-адрес/порт.**
*   `unix:/dev/shm/nginx-http.sock` — Локальный сокет, на который Nginx проксирует весь остальной HTTPS трафик из блока `stream`.

Убедитесь, что процесс `www-data` (Nginx) имеет права на чтение/запись этих сокетов, создаваемых Xray.

### 3. Локальные порты (Upstreams)
Убедитесь, что порты в блоке `upstream` соответствуют портам, настроенным в вашей панели 3x-ui для соответствующих Inbounds:
*   **Панель 3x-ui:** `127.0.0.1:49467`
*   **Подписки (Client Subscriptions):** `127.0.0.1:49158`
*   **VLESS XHTTP Packet-UP:** `127.0.0.1:11443`
*   **VLESS WebSocket:** `127.0.0.1:9443`
*   **VLESS XHTTP STREAM-ONE (gRPC):** `127.0.0.1:7443`

Если в панели порты отличаются, измените их в соответствующих блоках `upstream` и `location` в конфигурации Nginx.

### 4. Директории кэша и статики
Nginx требует наличия директорий для работы с кэшем. Выполните следующие команды от имени root:
```bash
mkdir -p /var/cache/nginx/img_cache
mkdir -p /var/cache/nginx/html_cache
mkdir -p /var/www/html
mkdir -p /var/www/mirror
mkdir -p /var/www/proxy_temp
chown -R www-data:www-data /var/cache/nginx
chown -R www-data:www-data /var/www
```

### 5. Секретные пути (Новые сгенерированные)
Вы должны обновить настройки в вашей панели 3x-ui, чтобы они соответствовали новым путям из конфигурации:
*   **Путь к панели (URL Root):** `/video/bitrate/hls/JWtmpbDP9HYkGoPe/`
*   **Путь к подпискам:** `/stream/master/playlist/Speede_log_wUmniWfwl7zcVJUHcziXXSIHFzyscLZ9yeED/`

## ⚙️ Что еще можно/нужно поменять под себя

1.  **Заголовок защиты `X-Request-ID`:**
    В конфигурации используется секретный заголовок для авторизации gRPC (STREAM-ONE) и XHTTP соединений:
    ```nginx
    map $http_x_request_id $xray_allow {
        default          0;
        "4dbe37b4b1d8196f" 1; # Ваш секретный ключ
    }
    ```
    Вы можете изменить `4dbe37b4b1d8196f` на свой уникальный ключ и обязательно прописать его в настройках клиентов (например, v2rayN, Nekobox) в разделе пользовательских заголовков.

2.  **SNI домены для Reality:**
    В блоке `stream -> map $ssl_preread_server_name` вы можете добавлять или изменять домены, которые будут маршрутизироваться на Reality сокеты (например, `taxi.yandex.ru`, `f1tv.formula1.com`).

3.  **Сайт для маскировки (Reverse Proxy):**
    В данный момент сервер маскируется под `animesss.com`. Если вы решите сменить домен маскировки, вам потребуется аккуратно заменить:
    *   `animess_backend` (строка `server animesss.com:443 resolve;`)
    *   Все вхождения `animesss.com` в правилах `proxy_pass`, `proxy_ssl_name`, `proxy_set_header Host`, `proxy_cookie_domain` и `sub_filter`.

## 🚀 Установка и проверка

1. Поместите этот конфигурационный файл в `/etc/nginx/nginx.conf` (или подключите его через `/etc/nginx/conf.d/`).
2. Проверьте синтаксис перед перезапуском:
   ```bash
   nginx -t
   ```
3. Если ошибок нет (появится сообщение `syntax is ok`), перезапустите Nginx:
   ```bash
   systemctl restart nginx
   ```

## 🛡️ Особенности защиты (Что здесь работает)
*   **Блокировка сканеров по IP:** Прямые запросы по IP-адресу сбрасываются (`ssl_reject_handshake on;`).
*   **Защита от активного зондирования (Anti-probing):** Все ошибки Xray (Bad Request, Gateway Timeout) перехватываются Nginx и маскируются под стандартную страницу 404 маскировочного сайта.
*   **Строгий фильтр ботов:** Встроенный черный список User-Agent'ов отсекает большинство известных поисковых ботов, сканеров уязвимостей и AI-скрейперов.
*   **Усиленное кэширование:** Nginx агрессивно кэширует статику сайта-маскировки, снижая нагрузку на бэкенд и ускоряя загрузку обманной страницы для проверяющих ботов.
